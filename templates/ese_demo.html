Screen 1: Project Introduction & Cryptographic Architecture

Overview

Welcome to the Secure Electronic Voting System built for the Cryptography and Information Security (CIS) End Semester Practical Examination. This project integrates exactly two core cryptographic concepts: RSA Public Key Cryptography and HMAC-SHA256 Authentication.

WHAT HAPPENED?
The application initialized its dual-layer cryptographic architecture. The election authority establishes an RSA asymmetric key pair and distributes HMAC credentials to voters.
WHY IS IT REQUIRED?
Electronic voting systems face dual threats: eavesdropping (violating voter confidentiality) and active packet tampering (violating ballot integrity). A dual-layer model solves both simultaneously.
WHICH SECURITY PROPERTY?
Comprehensive Security Architecture: Sets the foundation for Confidentiality, Integrity, and Authentication.

Screen 2: RSA Key Generation (p, q ➔ n, φ(n) ➔ e, d)

Asymmetric Math
Active Mathematical Parameters
Primes: p = {{ rsa.p }}, q = {{ rsa.q }}
Modulus: n = p × q = {{ rsa.p }} × {{ rsa.q }} = {{ rsa.n }}
Euler's Totient: φ(n) = (p - 1)(q - 1) = {{ rsa.p - 1 }} × {{ rsa.q - 1 }} = {{ rsa.phi }}
Public Exponent: e = {{ rsa.e }} (where gcd({{ rsa.e }}, {{ rsa.phi }}) = 1)
Private Exponent: d = {{ rsa.d }} (where {{ rsa.d }} × {{ rsa.e }} mod {{ rsa.phi }} = 1)
WHAT HAPPENED?
Selected primes p=61 and q=53. Computed modulus n=3233 and totient φ(n)=3120. Picked public exponent e=17 and derived private exponent d=2753 using Extended Euclidean Algorithm.
WHY IS IT REQUIRED?
Asymmetric key generation ensures that anyone can encrypt ballots using public key (e, n), but only the election server with private key (d, n) can decrypt them.
WHICH SECURITY PROPERTY?
Key Security & Foundation for Confidentiality: Separates public encryption from private decryption capability.

Screen 3: RSA Encryption (C = Me mod n)

Public Key Operation
Encryption Arithmetic Example
Plaintext (M) = 42
Formula: C = Me mod n = 4217 mod 3233
Ciphertext (C) = 2557
WHAT HAPPENED?
The plaintext number 42 was raised to public exponent e=17 modulo n=3233, producing the ciphertext integer 2557.
WHY IS IT REQUIRED?
Converts readable voter ballot selections into ciphertext integers before transmission over untrusted networks.
WHICH SECURITY PROPERTY?
Confidentiality: Prevents network eavesdroppers from discovering which candidate was chosen.

Screen 4: RSA Decryption (M = Cd mod n)

Private Key Operation
Decryption Arithmetic Trace
Ciphertext (C) = 2557
Formula: M = Cd mod n = 25572753 mod 3233
Recovered Plaintext (M) = 42 (Exact Match!)
WHAT HAPPENED?
The election server applied private exponent d=2753: 2557^2753 mod 3233, successfully recovering the original message 42.
WHY IS IT REQUIRED?
Allows the official election tabulation server to read the true vote choice for counting without relying on an insecure symmetric key.
WHICH SECURITY PROPERTY?
Confidentiality & Decryption Authorization: Only the possessor of the private key can recover the ballot.

Screen 5: HMAC-SHA256 Generation (RFC 2104)

Integrity Tag
RFC 2104 Pad Construction
Message: "Candidate_A" | Key: "VotingSecret123"
HMAC(K, M) = SHA256((K' ⊕ 0x5C) || SHA256((K' ⊕ 0x36) || M))
Tag: 2a979ceb36203cf3d2c69c6fcbe3aa64e62846dd6c4c5ea2b144fa54ebc52119
WHAT HAPPENED?
Applied inner pad (0x36) and outer pad (0x5C) XOR with the shared secret key and hashed twice with SHA-256 to generate a 256-bit tag.
WHY IS IT REQUIRED?
Protects the message against tampering and proves the sender knows the secret key. Simple hashing alone (SHA256(M)) provides no key authentication.
WHICH SECURITY PROPERTY?
Message Integrity & Authentication: Produces a cryptographic seal tied to both data and secret key.

Screen 6: Constant-Time HMAC Verification

Verification
Server Verification Step
Received Tag == Server_Calculated_Tag ?
Result: hmac.compare_digest() == TRUE
Status: ✓ Message Integrity Verified & Voter Authenticated
WHAT HAPPENED?
The server recalculated HMAC-SHA256 over the received message using its copy of the voter's secret key and executed constant-time comparison.
WHY IS IT REQUIRED?
Confirms that the message was not modified in transit and prevents side-channel timing attacks that could leak secret key bytes.
WHICH SECURITY PROPERTY?
Timing Attack Resistance & Authenticity: Validates payload origin without timing vulnerabilities.

Screen 7: Dual-Layer Secure Vote Submission

Integration

The voter submits their ballot. The payload is encrypted with RSA, and the transmission packet (Encrypted_Vote || Voter_ID || Timestamp) is authenticated with HMAC-SHA256.

WHAT HAPPENED?
Both cryptographic algorithms worked together in unison. RSA sealed the candidate choice, while HMAC sealed the transmission packet.
WHY IS IT REQUIRED?
Neither algorithm is sufficient alone: RSA alone doesn't detect unauthorized active payload tampering without certificates; HMAC alone does not encrypt data.
WHICH SECURITY PROPERTY?
Integrated Confidentiality + Integrity + Authentication: Complete end-to-end voting protection.

Screen 8: Man-in-the-Middle Tampering Simulation

Attack Phase
Active Adversary Interception
Voter's Intended Vote: Candidate A
Adversary Modifies Payload To: Candidate B
Transmitted HMAC Tag: Kept as original (Adversary lacks secret key)
WHAT HAPPENED?
An active network attacker intercepted the transmission packet and flipped the vote choice from Candidate A to Candidate B without updating the HMAC tag.
WHY IS IT REQUIRED?
Demonstrates real-world threats where malicious actors or compromised proxies try to manipulate election outcomes in transit.
WHICH SECURITY PROPERTY?
Active Threat Simulation: Simulates a violation of message integrity to test defense readiness.

Screen 9: Tampering Detected & Vote Rejected

🚨 ALARM TRIGGERED
Server Verification Evaluation
Original HMAC ≠ Server Recalculated HMAC
Result: 🚨 TAMPERING DETECTED
Server Action: VOTE REJECTED IMMEDIATELY (Never decrypted or tallied!)
WHAT HAPPENED?
The server recalculated HMAC over the tampered payload. Because HMAC is keyed with a secret the attacker does not possess, the tag mismatched and the vote was discarded!
WHY IS IT REQUIRED?
Ensures forged or modified ballots never contaminate the election database or alter tally totals.
WHICH SECURITY PROPERTY?
Tamper Detection & Non-Repudiation: Guarantees that corrupted votes cannot be successfully submitted.

Screen 10: Decrypted Ledger Tally & Audit Trail

Final Election Result

Legitimate, verified votes are decrypted using the server's RSA private key (d, n) and recorded in the SQLite ledger under a pseudonymous hash to protect voter anonymity.

WHAT HAPPENED?
Only authenticated, untampered ballots were decrypted and included in the election tally. The audit log maintains a transparent record of all operations.
WHY IS IT REQUIRED?
Provides verifiable, transparent election results while maintaining separation between voter identity and ballot choice.
WHICH SECURITY PROPERTY?
Auditing & Election Integrity: Delivers provable, tamper-resistant election tally outcomes.
