Demonstrated Availability Protections

How the system maintains availability under adversarial or erroneous conditions
Fault Tolerance

1. Duplicate Voting Prevention

If a voter attempts to submit a second ballot:

Vote already recorded. You cannot submit another vote.

The system returns a structured HTTP 400 rejection and remains 100% operational rather than crashing.

2. Malformed Request Handling

If invalid parameters or corrupt JSON are received:

Request rejected safely. Voting service remains operational.

Input validation filters bad packets before they reach cryptographic or storage routines.

3. Exception & Failure Isolation

Unexpected errors are handled cleanly:

Internal state isolated. Stack traces are never exposed.

ACID transactional rollbacks prevent partial database writes and preserve ledger consistency.

Key Architectural Principle

Availability is supported by reliable application design, schema validation, duplicate-voting prevention, and resilient error recovery—not by RSA or HMAC themselves. Neither asymmetric encryption nor cryptographic hash functions ensure that a server remains online or that duplicate ballots are rejected; those guarantees are provided by the application architecture and database constraints.
