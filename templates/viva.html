1. RSA Cryptography Viva Questions

Q1. What is RSA?▼
Answer: RSA (named after Ron Rivest, Adi Shamir, and Leonard Adleman) is an asymmetric public-key cryptographic algorithm. It relies on the mathematical difficulty of factoring the product of two large prime numbers (the integer factorization problem).
Q2. Why is RSA called an asymmetric algorithm?▼
Answer: It is asymmetric because it uses a mathematically linked pair of different keys: a Public Key (e, n) used for encryption, and a distinct Private Key (d, n) used for decryption. Knowledge of the public key does not easily reveal the private key.
Q3. What is a public key in RSA?▼
Answer: The public key consists of the pair (e, n), where n is the modulus (n = p × q) and e is the public exponent. It is freely distributed to all voters so they can encrypt their ballots.
Q4. What is a private key in RSA?▼
Answer: The private key consists of (d, n), where d is the private exponent calculated as the modular multiplicative inverse of e mod φ(n). It must be kept strictly secret on the election server to decrypt ballots.
Q5. What is Euler's totient function φ(n)?▼
Answer: Euler's totient φ(n) counts the number of positive integers strictly less than n that are coprime (relatively prime) to n. For prime numbers p and q, φ(n) = (p - 1)(q - 1). It is essential because by Euler's theorem, M^φ(n) ≡ 1 (mod n), which allows calculating private exponent d.
Q6. What is the RSA key generation process?▼
Answer: 1. Select two distinct prime numbers p and q.
2. Compute modulus n = p × q.
3. Compute totient φ(n) = (p - 1)(q - 1).
4. Select public exponent e such that 1 < e < φ(n) and gcd(e, φ(n)) = 1.
5. Calculate private exponent d ≡ e⁻¹ mod φ(n) using the Extended Euclidean Algorithm (d × e ≡ 1 mod φ(n)).
6. Public key is (e, n); Private key is (d, n).
Q7. What is the RSA encryption formula?▼
Answer: C = M^e mod n, where M is the plaintext integer (such that 0 ≤ M < n), e is the public exponent, and C is the resulting ciphertext integer.
Q8. What is the RSA decryption formula?▼
Answer: M = C^d mod n, where C is the ciphertext integer, d is the private exponent, and M is the recovered plaintext integer.
Q9. Why does RSA rely on prime numbers?▼
Answer: Multiplying two large prime numbers p × q = n is computationally easy (polynomial time), but finding p and q given only n is computationally intractable (sub-exponential time). Without knowing p and q, an attacker cannot compute φ(n) and therefore cannot deduce private exponent d.
Q10. Why is RSA not suitable for encrypting large amounts of data?▼
Answer: RSA modular exponentiation of very large integers (e.g. 2048-bit numbers) is computationally expensive, requiring extensive CPU arithmetic. Furthermore, RSA can only encrypt messages smaller than its modulus n. In real applications, a hybrid cryptosystem is used: RSA encrypts a small symmetric session key (e.g. AES), and AES encrypts the bulk data.
Q11. What is the difference between RSA Encryption and RSA Digital Signatures?▼
Answer: In RSA Encryption, anyone uses the receiver's Public Key to encrypt (C = M^e mod n), and only the receiver uses their Private Key to decrypt (M = C^d mod n) for Confidentiality. In RSA Digital Signatures, the sender uses their Private Key to sign the hash (S = H(M)^d mod n), and anyone uses the sender's Public Key to verify (H(M) = S^e mod n) for Authentication & Non-repudiation.

2. HMAC-SHA256 Authentication Viva Questions

Q12. What is HMAC?▼
Answer: HMAC stands for Hash-based Message Authentication Code (RFC 2104). It is a cryptographic mechanism that uses a cryptographic hash function in combination with a secret shared key to verify both data Integrity and data Authenticity.
Q13. What does HMAC-SHA256 mean?▼
Answer: It means an HMAC construction using SHA-256 as the underlying cryptographic hash function, outputting a 256-bit (32-byte / 64-hexadecimal character) authentication tag.
Q14. What is SHA-256?▼
Answer: SHA-256 is a member of the SHA-2 family designed by the NSA. It is a cryptographic one-way hash function that takes an arbitrary-length message and produces a fixed-size 256-bit digest with strong collision resistance and preimage resistance.
Q15. Is SHA-256 an encryption algorithm?▼
Answer: NO! SHA-256 is a one-way mathematical hash function, not encryption. Encryption is a two-way operation that can be reversed with a decryption key. A hash function cannot be decrypted because information is compressed irreversibly.
Q16. Is HMAC an encryption algorithm?▼
Answer: NO! HMAC is a message authentication code, not an encryption cipher. The message remains unencrypted unless an encryption algorithm (like RSA) is also applied. HMAC provides integrity and authenticity, but zero confidentiality.
Q17. Why is a secret key required in HMAC?▼
Answer: Without a secret key, an attacker modifying a message could simply recalculate a standard hash (e.g. SHA256(tampered_msg)) and replace it. With HMAC, calculating the correct tag requires possession of the secret key K, which the attacker does not have.
Q18. What happens if the message changes by even a single character?▼
Answer: Due to the avalanche effect of SHA-256, changing even a single bit in the message changes approximately 50% of the bits in the resulting hash digest. The newly calculated HMAC will completely diverge from the original tag, causing immediate verification failure.
Q19. Why not simply use SHA256(key + message) instead of HMAC?▼
Answer: The naive construction H(key || message) is vulnerable to Length Extension Attacks in Merkle-Damgård hash functions like SHA-256. An attacker can append data to the message and forge a valid hash without knowing the secret key. HMAC prevents this by using inner and outer padding (ipad = 0x36 and opad = 0x5C).
Q20. Does HMAC provide confidentiality?▼
Answer: NO. HMAC does not conceal or encrypt the data. Anyone intercepting the payload can read it if it is not encrypted. This is precisely why our project combines HMAC with RSA!
Q21. What is the difference between HMAC and a Digital Signature?▼
Answer: HMAC is a symmetric mechanism: both sender and receiver share the same secret key K. Any party with K can generate or verify the tag (no non-repudiation between parties sharing K). A Digital Signature is asymmetric: the sender signs using their private key, and anyone can verify using the sender's public key, providing true non-repudiation to third parties.

3. Project Architecture & Integration Viva Questions

Q22. Why did you choose RSA for this project?▼
Answer: RSA was selected to provide Confidentiality via asymmetric public key cryptography. Voters can encrypt their ballots using the publicly available server key (e, n) without needing to share or reveal the private key (d, n).
Q23. Why did you choose HMAC-SHA256 for this project?▼
Answer: HMAC-SHA256 was selected to provide Integrity and Authentication. It guarantees that the vote request was not modified in transit by an adversary and verifies that the submission came from an authorized voter possessing the secret key.
Q24. Why do you need BOTH RSA and HMAC-SHA256?▼
Answer: Because each algorithm solves a different security requirement: • RSA alone protects confidentiality, but an active attacker on the network could tamper with the ciphertext bits or inject forged ballots without detection.
• HMAC alone detects tampering, but does not encrypt the ballot (plaintext would be exposed).
Combined: RSA hides the vote, while HMAC detects tampering and authenticates the voter.
Q25. How does your system detect vote tampering?▼
Answer: The client submits (Encrypted_Vote, HMAC_Tag, Voter_ID, Timestamp). The server independently recomputes Calculated_HMAC = HMAC(Voter_Secret, Canonical_Payload). If an attacker modified the payload in transit, the calculated HMAC will not match the received tag. The server calls hmac.compare_digest(), detects the mismatch, logs a security alarm, and rejects the vote immediately without decrypting it.
Q26. What happens if an attacker changes Candidate A to Candidate B?▼
Answer: If an active attacker flips the candidate payload, the server recomputes the HMAC over the tampered payload. Because the attacker lacks the voter's secret key, they cannot forge the matching HMAC. The server detects that Received_HMAC ≠ Calculated_HMAC and returns an HTTP 400 TAMPERING_DETECTED alert.
Q27. How does the project provide Confidentiality, Integrity, and Authentication?▼
Answer: • Confidentiality: RSA public key encryption (C = M^e mod n) ensures only the election authority with private key d can read the ballot.
• Integrity: HMAC-SHA256 verifies that not a single bit was changed in transit.
• Authentication: Possession of the voter's unique HMAC shared secret proves the voter's identity.
• Password Protection: Login passwords are protected using salted SHA-256 password hashing.
Q28. What are the limitations of this educational system?▼
Answer: As an educational prototype for CIS viva evaluation, it uses small primes for visible math and SQLite storage. Real-world elections additionally require: homomorphic encryption for anonymous tallying, Hardware Security Modules (HSMs) for private keys, PKI certificates, coercion resistance, and End-to-End Verifiability (E2E-V).
