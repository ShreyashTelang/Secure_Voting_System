How HMAC-SHA256 Works (RFC 2104 Specification)

Keyed-Hash Message Authentication Code (HMAC) is specified in RFC 2104 and NIST FIPS 198-1. It provides data integrity and authenticity by combining a secret key with an underlying cryptographic hash function (SHA-256).

Standard RFC 2104 Construction Formula
HMAC(K, m) = H((K' ⊕ opad) || H((K' ⊕ ipad) || m))
Component Value / Definition Cryptographic Purpose
K Shared Secret Key Confidential key known only to the voter and the election server.
K' Normalized Key (64 bytes) If key > 64 bytes, SHA-256(K) is used; if < 64 bytes, zero-padded to 64 bytes.
ipad Inner Pad: 0x36 repeated 64-byte constant used to compute inner hash (K' ⊕ ipad).
opad Outer Pad: 0x5C repeated 64-byte constant used to compute outer hash (K' ⊕ opad).
m Voting Payload Message The exact canonical ballot data string (e.g. candidate=Elena Rostova).
H SHA-256 Hash Function Produces a fixed 256-bit (32-byte / 64-hexadecimal character) output digest.
Why HMAC is Stronger Than Simple Hash Concatenation (e.g., H(key || message))

Naive constructions such as H(key || message) are vulnerable to Length Extension Attacks when using Merkle–Damgård hash algorithms like SHA-256. An attacker who knows the message and tag can compute a valid tag for message || padding || extension without knowing the secret key.

HMAC's nested inner and outer passes prevent length extension by hashing the intermediate hash with an outer key-derived mask (K' ⊕ opad). This guarantees pseudo-randomness and unforgeability.

Where RSA Fits in the SecureVote Architecture

Understanding the dual-layer roles of RSA Asymmetric Encryption and HMAC Message Authentication
Dual Security
RSA Public-Key Cryptography
CONFIDENTIALITY

Protects the voter's candidate selection from eavesdropping, network sniffers, and intermediate proxies.

  • Voter encrypts ballot using Election Authority public key: C = M^e mod n.
  • Only the server possessing private key d can recover M = C^d mod n.
  • Ensures ballot secrecy and anonymous tallying.
HMAC-SHA256 Keyed Authentication
INTEGRITY & AUTHENTICATION

Protects the transmission envelope against tampering, injection, and unauthorized parameter modification.

  • Computes 256-bit authentication tag over request payload using shared secret.
  • Server re-hashes received payload and verifies with hmac.compare_digest.
  • Ensures modified votes are immediately rejected before decryption.
Security Synthesis: "RSA ensures that unauthorized parties cannot read protected data. HMAC-SHA256 ensures that data has not been modified in transit." Together, they guarantee that every counted vote is both private and authentically cast.
